# Сортировка выбором

## Идея

На каждой итерации алгоритм ищет минимальный элемент необработанной части и помещает его на первую позицию этой части.

## Реализация

```java
public static void selectionSort(int[] array) {
    for (int out = 0; out < array.length - 1; out++) {
        int minIndex = out;

        for (int in = out + 1; in < array.length; in++) {
            if (array[in] < array[minIndex]) {
                minIndex = in;
            }
        }

        if (minIndex != out) {
            int temp = array[out];
            array[out] = array[minIndex];
            array[minIndex] = temp;
        }
    }
}
```

## Инвариант

Перед итерацией с индексом `out` диапазон `[0, out)` содержит наименьшие элементы массива в окончательном порядке.

## Почему нельзя завершить поиск при `minIndex == out`

Это означает только, что первый элемент текущей части уже минимальный. Остальные элементы могут оставаться неотсортированными. Например, после первого шага в `[1, 3, 2]` единица уже стоит правильно, но `3` и `2` ещё нужно переставить.

## Сложность

- Лучший, средний и худший случаи: `O(n²)`.
- Дополнительная память: `O(1)`.
- Число обменов не превышает `n - 1`.

## Обнаруженная ошибка

`minIndex` хранит индекс, поэтому сравнивать нужно значения массива:

```java
array[in] < array[minIndex]
```

Сравнение `array[in] < minIndex` сопоставляет значение элемента с номером позиции и нарушает алгоритм.
